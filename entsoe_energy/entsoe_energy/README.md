# ENTSO-E Energy Price Pipeline

A small end-to-end data engineering project that extracts Romanian day-ahead electricity prices from the ENTSO-E Transparency Platform, loads the data into DuckDB using dlt, transforms and validates it with dbt, and generates a daily price report.

The project demonstrates a complete local workflow using Python, dlt, DuckDB, dbt and SQL.

---

## Project Overview

The pipeline follows this flow:

```text
ENTSO-E API
    ↓
Python extraction + XML parsing
    ↓
Timezone-aware date handling
    ↓
dlt ingestion
    ↓
DuckDB raw data
    ↓
dbt staging + tests
    ↓
dbt daily mart
    ↓
Daily price report
```

The pipeline works with Romanian calendar dates using the `Europe/Bucharest` timezone.

ENTSO-E returns timestamps in UTC, so the requested Romanian day is first converted to the correct UTC interval.

For example:

```text
Romanian date:
2026-08-26

UTC API interval:
202608252100 -> 202608262100
```

The data has 15-minute resolution, so a normal 24-hour day contains:

```text
96 observations
```

### `data/`

Contains the local DuckDB analytical database.

- `energy.duckdb` — stores the raw ENTSO-E observations loaded by dlt and the models generated by dbt.

The main database objects are:

```text
raw.raw_entsoe_prices
        ↓
main.stg_entsoe_prices
        ↓
main.daily_prices
```

---

### `src/`

Contains the Python code responsible for extracting, processing, loading and reporting the data.

- `entsoe_api.py` — communicates with the ENTSO-E API, calculates the correct UTC interval for a Romanian calendar day, retrieves the XML response and parses the 15-minute electricity price observations.

- `dlt_pipeline.py` — defines the dlt ingestion pipeline and loads the parsed price records into DuckDB. It uses merge behavior with the timestamp as the primary key.

- `report.py` — reads the transformed `daily_prices` table from DuckDB and prints the final daily electricity price report.

---

### `dbt_energy/`

Contains the dbt transformation and data quality layer.

The dbt project transforms the raw data loaded by dlt into clean analytical models and validates the data before producing the final daily dataset.

#### `dbt_energy/models/staging/`

Contains the staging layer.

- `sources.yml` — defines the DuckDB raw table created by dlt as a dbt source.

- `stg_entsoe_prices.sql` — transforms the raw ENTSO-E observations into a clean staging model and derives the Romanian price date.

- `stg_entsoe_prices.yml` — contains schema documentation and column-level data quality tests.

The resulting staging model is:

```text
main.stg_entsoe_prices
```

with fields such as:

```text
timestamp
price_eur_mwh
price_date
```

---

#### `dbt_energy/models/marts/`

Contains the final analytical models.

- `daily_prices.sql` — aggregates the 15-minute electricity prices by day.

For each date it calculates:

```text
average price
minimum price
maximum price
number of observations
```

The resulting table is:

```text
main.daily_prices
```

---

#### `dbt_energy/tests/`

Contains custom SQL data quality tests.

- `no_duplicate_timestamps.sql` — checks that the dataset does not contain duplicate electricity price timestamps.

- `price_sanity_check.sql` — checks that electricity prices remain within the expected sanity range.

Together with the schema tests, the dbt project currently runs five data tests.

## Pipeline Components

### 1. ENTSO-E API

`src/entsoe_api.py` handles communication with the ENTSO-E Transparency Platform.

It:

- loads the API token from environment variables;
- sends the API request;
- retrieves the XML response;
- parses 15-minute electricity price observations;
- converts timestamps to timezone-aware records;
- keeps only records that belong to the requested Romanian calendar date.

Because ENTSO-E returns UTC timestamps, the pipeline converts the Romanian local day into the correct UTC interval before requesting the data.

---

### 2. dlt Ingestion

`src/dlt_pipeline.py` loads the parsed records into DuckDB.

The raw table is:

```text
raw.raw_entsoe_prices
```

The main fields are:

```text
timestamp
price_eur_mwh
```

The dlt resource uses merge behavior with `timestamp` as the primary key, so rerunning the same date does not create duplicate timestamps.

---

### 3. DuckDB

DuckDB is used as the local analytical database.

The database is stored in:

```text
data/energy.duckdb
```

The data flow inside DuckDB is:

```text
raw.raw_entsoe_prices
        ↓
main.stg_entsoe_prices
        ↓
main.daily_prices
```

The database keeps historical dates, so previously loaded data remains available after new pipeline runs.

---

### 4. dbt

dbt is responsible for transformations and data quality.

The project contains:

- staging model: `stg_entsoe_prices`
- daily mart: `daily_prices`
- five data tests
- SQL-based quality checks

The tests verify conditions such as:

- timestamps are not null;
- prices are not null;
- timestamps are unique;
- prices are within a reasonable range.

A successful dbt run finishes with:

```text
PASS=7
WARN=0
ERROR=0
SKIP=0
```

---

### 5. Daily Report

`src/report.py` generates a daily summary containing:

- average price;
- minimum price;
- maximum price;
- number of observations.

Example:

```text

--------------------------------------------------------------------------------

2026-08-19              167.65         123.35         224.07             96

2026-08-21              169.56          55.98         229.78             96
2026-08-26              185.27         116.41         261.57             96
```

The report shows all historical dates currently stored in DuckDB.

## Running the Pipeline

Run the complete pipeline with:

```powershell
python run_pipeline.py
```

When no date is provided, the pipeline processes yesterday.

You can also provide a specific date:

```powershell
python run_pipeline.py 2026-08-26
```

The main script runs:

```text
1. ENTSO-E ingestion
2. dbt build
3. Daily price report
```

The ENTSO-E API token is stored in a local `.env` file.

Example:

```text
ENTSOE_API_TOKEN=your_api_token_here
```

The `.env` file must be excluded from Git and should never be committed to GitHub.
